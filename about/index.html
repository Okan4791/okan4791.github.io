About

I like software that
explains itself.

I build practical tools near the boundary between people and their systems. A clear status, safe default, or repeatable command can save an afternoon.

Working principles

Make the state visible.

Whether it is a privacy device, DNS record, or launch chain, people should be able to see what the tool believes and what it will do next.

Prefer boring dependencies.

Small tools benefit from platform capabilities, plain formats, and escape hatches. The implementation should be easy to inspect and repair.

Design the recovery path.

Failures happen. A useful tool reports them precisely, preserves context, and gives the operator a clear next move.
