Work/AUR Response Toolkit

Security · Rust

Evidence first.
Recovery second.

A native toolkit for detecting, triaging, and recovering from documented Arch User Repository supply-chain incidents.

Role
Research, design, and implementation
Modes
Offline · Online · JSON · Interactive
Project
Project site ↗

Condition

An AUR incident scan could look clean without being complete.

Supply-chain incidents leave evidence across installed packages, ALPM timelines, build artifacts, persistence paths, and shell history. Responders needed offline detection, current incident data, and guarded recovery from one tool.

A missed root or unreadable file had to remain visible instead of disappearing behind a clean result.

Cause

Evidence, source trust, and scan coverage are separate facts.

Finding no compromise indicator says nothing about evidence the scanner could not inspect. Treating those outcomes as equivalent creates false confidence.

Incident lists also change over time. Replacing a known local baseline with an unverified online response would trade freshness for trust.

Correction

Track coverage and provenance alongside every finding.

Bundled campaign lists support offline scans. Online scans atomically cache parsed updates while retaining the trusted baseline, and an integrity manifest protects the IOC registry and bundled lists.

Reports record retrieval dates, source details, hashes, and coverage counters. Incomplete coverage returns a distinct status even when the engine finds no indicator. Recovery requires a dry run, explicit application, backups, and post-action verification.

Confirm

Detection and recovery produce one auditable record.

Package, timeline, artifact, IOC, audit, and hardening checks produce text or JSON reports. Each report preserves what was checked, what was missed, which data was trusted, and which recovery actions ran.

Native Rust tests verify command routing, exit policy, report schemas, compressed logs, list integrity, incomplete coverage, and recovery safeguards.
