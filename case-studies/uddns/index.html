Condition

One service had to keep many DNS providers in sync.

Each hostname needed an update when its public IPv4 or IPv6 address changed. Several accounts could run together, and a failure for one host could not trigger repeat updates for hosts that had already succeeded.

The service also needed to distinguish a real address change from a temporary discovery or provider failure.

Cause

Providers share a goal, but not a protocol.

Authentication, record lookup, response shapes, and dual-stack behavior vary by provider. Treating those differences inside one update loop would couple core state management to every provider API.

A shared checkpoint would spread failures across hosts, while ordinary URL validation could still allow requests to resolve to unsafe network destinations.

Correction

Isolate provider variation and checkpoint each host.

Each provider implements one registered update interface. Configuration is schema-validated, unsupported keys fail early, and every host receives an independent atomic checkpoint.

Public-IP and provider requests use pin-on-connect HTTPS. The client rejects loopback, link-local, metadata, and private destinations by default, then connects only to verified addresses. Transient failures use bounded retry with jitter and honor Retry-After.

Confirm

The same core now supports fifteen provider families.

That core runs as a long-lived daemon, a one-shot CLI, a Docker deployment, or an optional MCP transport. Multi-account YAML can define ordered failover for hostnames served by more than one provider.

Documentation-contract tests verify provider IDs, defaults, commands, and security allowlists against the implementation.
