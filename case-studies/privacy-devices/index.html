Condition

Privacy activity was visible only in scattered system signals.

Microphones, cameras, location, screen sharing, screenshots, and recording expose state through different Linux interfaces. Users needed one place to see activity, control devices, and understand failures.

The same view also had to work across multiple monitors without duplicating background observers.

Cause

Those signals do not share a reliable state model.

An observer restart can make an active session disappear without a real stop event. A command can return successfully before the requested device state takes effect, and duplicated observers can race for state and IPC ownership.

Treating each bar widget as its own monitor would multiply those gaps instead of resolving them.

Correction

Centralize observation and verify every control request.

One long-lived service owns normalized sessions, observers, controls, health, notifications, history, and IPC. Bar widgets read that shared state without starting another monitoring stack.

A control stays pending until observed state matches the request or a bounded timeout expires. Observer recovery invalidates source-owned sessions without inventing stop events, and the first uncertain snapshot does not trigger a new-activity alert.

Confirm

Seven device classes now report through one bounded service.

The plugin reports per-application context and supports per-endpoint audio controls, named privacy modes, diagnostics, and optional bounded history.

Persistent observers use heartbeats and bounded restart backoff. The service sends no network telemetry, and command helpers accept only narrow allowlisted actions.
