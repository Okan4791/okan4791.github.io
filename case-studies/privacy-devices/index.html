Problem

Linux privacy activity arrives through several imperfect sources.

Microphones, cameras, location, screen sharing, screenshots, and recording do not share one state model. Signals can disappear when an observer restarts, and a command returning successfully does not prove the device changed.

Multi-monitor presentation adds another risk: duplicated observers can race for state and IPC ownership.

Decision

Centralize monitoring and treat controls as transactions.

One long-lived service owns normalized sessions, observers, controls, health, notifications, history, and IPC. Bar widgets project that shared state without starting another monitoring stack.

A control remains pending until observed state matches the request or a bounded timeout expires. Observer recovery invalidates source-owned sessions without inventing stop events, and the first uncertain snapshot is not announced as new activity.

Result

Visible state, verified actions, and bounded background work.

The plugin covers seven privacy-device classes with per-application context, per-endpoint audio controls, named privacy modes, diagnostics, and optional bounded history.

Persistent observers use heartbeats and bounded restart backoff. There is no network telemetry, and command helpers accept narrow allowlisted actions.
